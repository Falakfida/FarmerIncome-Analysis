## 1. Project Overview

This project analyses the income of Indian farmers using the **LTE (Land, Terrain, and Economy) dataset** — a rich tabular dataset covering agricultural performance, weather conditions, socio-economic indicators, and financial bureau data across multiple Kharif and Rabi crop seasons (2020–2022).

**Goal:** Build a production-ready regression model that accurately predicts a farmer's total annual income (agriculture + non-agriculture) and expose it through a web interface.

**Key outcomes:**
- R² ≈ 0.81 on held-out test data
- Mean Absolute Percentage Error ≈ 9%
- Interactive Streamlit dashboard for real-time predictions and dataset exploration

## 4. Data Cleaning & Preprocessing

### 4.1 Column Name Normalisation
All column names are stripped of leading/trailing whitespace to avoid key-mismatch errors.

### 4.2 Duplicate Removal
Exact duplicate rows are identified and removed using `pandas.DataFrame.drop_duplicates()`.

### 4.3 Missing Value Handling

| Column(s) | Missing% | Strategy |
|-----------|---------|---------|
| `Location`, `Address type`, `Ownership` | ~36% | Categorical mode imputation |
| `Avg_Disbursement_Amount_Bureau` | ~47% | Numeric median imputation |
| Household percentage columns | ~0.6% | Numeric median imputation |

All imputation is performed **inside the scikit-learn pipeline** using `SimpleImputer`, ensuring no data leakage between train and test sets.

### 4.4 Identifier Column Removal
Columns `FarmerID`, `Zipcode`, `VILLAGE`, `CITY`, `DISTRICT`, `Location`, and `K022-Nearest Mandi Name` are dropped (high cardinality / identifiers that don't generalise).

### 4.5 Temperature Parsing
Temperature columns store strings like `"23.34 /30.33"` (min/max pairs). These are parsed into their **arithmetic mean** to yield a single numeric value.

### 4.6 Categorical Standardisation
- **SEX**: mapped to `M`, `F`, or `Unknown`
- **MARITAL_STATUS**: mapped to `M`, `S`, `D`, `W`, or `Unknown`
- **Village quality columns** (`Good, Average, Poor`): ordinal-encoded → `Good=2, Average=1, Poor=0`

### 4.7 Outlier Treatment
The target variable is winsorised at the 1st and 99th percentiles to remove extreme outliers that would distort loss functions during training.

### 4.8 High-Cardinality Categorical Drop
Any object column with more than 50 unique values (e.g. Mandi names, village-level text) is dropped to avoid dimensionality explosion.

## 5. Feature Engineering

| New Feature | Formula / Logic | Purpose |
|-------------|----------------|---------|
| `avg_kharif_agri_score` | Mean of all Kharif season agri scores (2020–2022) | Aggregate season quality |
| `avg_rabi_agri_score` | Mean of all Rabi season agri scores (2020–2022) | Aggregate season quality |
| `overall_agri_score` | Mean of Kharif + Rabi scores | Single productivity proxy |
| `avg_rainfall` | Mean across all seasonal rainfall columns | Weather summary |
| `avg_temperature` | Mean across all parsed temperature columns | Climate summary |
| `Agriculture_Income` | `Total Income − Non_Agriculture_Income` | Pure agri income |
| `non_agri_income_ratio` | `Non_Agriculture_Income / Total_Income` | Income source mix |

After engineering, raw seasonal score and rainfall columns are dropped to eliminate multicollinearity.

## 6. Model Selection & Training

### Why Regression?
The target variable (`Target_Variable/Total Income`) is a continuous numeric quantity (INR), making regression the correct task type.

### Log Transformation of Target
The raw income distribution is right-skewed (skewness > 3). The target is log-transformed (`log1p`) before training, which:
- Stabilises variance
- Prevents large-income samples from dominating the loss
- Predictions are inverse-transformed (`expm1`) for reporting

### Model Comparison

| Model | MAE (₹) | RMSE (₹) | R² | MAPE |
|-------|--------|---------|-----|------|
| Ridge Regression | ~3,20,000 | ~5,40,000 | ~0.62 | ~28% |
| Random Forest | ~1,40,000 | ~3,10,000 | ~0.77 | ~12% |
| **XGBoost (selected)** | **~1,08,000** | **~2,60,000** | **~0.81** | **~9%** |

### XGBoost Hyperparameters

```python
XGBRegressor(
    n_estimators     = 600,
    learning_rate    = 0.05,
    max_depth        = 6,
    subsample        = 0.8,
    colsample_bytree = 0.8,
    min_child_weight = 3,
    reg_alpha        = 0.1,    # L1 regularisation
    reg_lambda       = 1.0,    # L2 regularisation
    tree_method      = 'hist'  # fast histogram-based algorithm
)
```

### Train/Test Split
- 80% training, 20% test, stratified split with `random_state=42`
- 5-fold cross-validation performed on the training set

## 7. Evaluation Results

| Metric | Value | Meaning |
|--------|-------|---------|
| **R²** | 0.806 | Model explains 80.6% of income variance |
| **MAE** | ₹1,07,951 | Average prediction error ≈ ₹1.1 Lakh |
| **RMSE** | ₹2,59,999 | Penalised error sensitive to large misses |
| **MAPE** | 9.01% | Average relative error of 9% |
| **CV R² (5-fold)** | ~0.80 ± 0.01 | Stable generalisation — no overfitting |

### Key Insights
- **Non-Agriculture Income** is the strongest individual predictor
- **Total Land for Agriculture** positively correlates with income (diminishing returns)
- **Village Socio-Economic Score** is highly influential — infrastructure quality drives income
- Madhya Pradesh and Rajasthan farmers show lower median incomes than Maharashtra/Karnataka
- Seasonal rainfall has moderate positive impact; temperature shows an inverse relationship

## 9. How to Run

**Option A — Jupyter Notebook (recommended):**
```bash

# Run all cells (Kernel → Restart & Run All)
```

**Option B — Convert to script and run directly:**
```bash
jupyter nbconvert --to script farmer_income_analysis.ipynb
python farmer_income_analysis.py
```

This will:
- Load and preprocess `lte_train.csv`
- Train the XGBoost model
- Save `farmer_income_model.joblib` and `feature_config.json`
- Generate EDA plots: `eda_target_distribution.png`, `eda_categorical.png`, `feature_importance.png`, `model_evaluation.png`

### Step 2: Launch the Streamlit UI

```bash
streamlit run farmer_income_app.py
```

The app will open at `http://localhost:8501`

## 11. Interpreting Results

### Income Bands

| Band | Range | Interpretation |
|------|-------|---------------|
| Low Income | < ₹5 Lakh | Subsistence-level farming, high financial risk |
| Lower-Middle | ₹5–10 Lakh | Basic needs met, limited savings |
| Middle | ₹10–20 Lakh | Stable income, moderate investment capacity |
| High Income | > ₹20 Lakh | Diversified income, strong financial profile |

### Model Confidence
- MAPE of ~9% means predictions are typically within 9% of actual income
- For a farmer with ₹10 Lakh actual income, predictions will typically fall in the ₹9.1–10.9 Lakh range
- The model is most accurate in the ₹7–15 Lakh range (densest training data)
